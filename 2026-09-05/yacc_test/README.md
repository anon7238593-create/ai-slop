# Yacc Expression Parser

This directory contains a small calculator-like parser for expressions made
from positive integer literals, `+`, and `-`. For example:

```text
1 + 1 - 3
```

The parser evaluates the expression from left to right and prints:

```text
Result: -1
```

## Files

### `expression.y`

This is the Yacc grammar. Yacc reads it and generates two files:

- `y.tab.c`, the generated parser implementation.
- `y.tab.h`, the generated token declarations used by the C lexer.

Line by line:

```c
%{
#include <stdio.h>
#include <stdlib.h>

int yylex(void);
void yyerror(const char *message);
%}
```

- `%{` begins a block of C code copied into the generated parser.
- `#include <stdio.h>` makes standard input/output declarations available.
- `#include <stdlib.h>` includes general-purpose C declarations. It is
  currently harmless but not required by the grammar.
- `int yylex(void);` declares the lexer function. The generated parser calls
  this function whenever it needs another token.
- `void yyerror(const char *message);` declares the error-reporting function
  called by the generated parser when input does not match the grammar.
- `%}` ends the copied C block.

```c
%token NUMBER
```

- `%token NUMBER` declares `NUMBER` as a named terminal token. Yacc assigns it
  a numeric value and writes that value to `y.tab.h`.

```c
%%
```

- The first `%%` separates declarations from grammar rules.

```c
input:
    expression '\n' { printf("Result: %d\n", $1); }
    ;
```

- `input:` defines the grammar's start rule.
- `expression '\n'` requires one complete expression followed by a newline.
- The action in braces is C code executed after the rule matches.
- `$1` refers to the semantic value produced by `expression`, so it is the
  calculated integer result.
- `printf` displays that result.
- `;` terminates the `input` rule.

```c
expression:
    NUMBER          { $$ = $1; }
    | expression '+' NUMBER { $$ = $1 + $3; }
    | expression '-' NUMBER { $$ = $1 - $3; }
    ;
```

- `expression:` begins the rules for an expression.
- `NUMBER` makes a number a valid expression.
- `$$ = $1` assigns the number's value to the result of the whole expression.
- `|` introduces another alternative production.
- `expression '+' NUMBER` matches an existing expression, a plus sign, and a
  number. Its action adds the existing result (`$1`) to the new number (`$3`).
- `expression '-' NUMBER` works the same way but subtracts `$3` from `$1`.
- The recursive structure makes sequences such as `1 + 1 - 3` valid and
  evaluates them from left to right.
- The second `%%` separates grammar rules from optional trailing C code. This
  grammar has no trailing C code.

### `expression.c`

This is the hand-written C glue code. It supplies the lexer, parser error
handler, and program entry point.

```c
#include <stdio.h>
```

- Includes declarations for `getchar`, `ungetc`, `scanf`, and `fprintf`.

```c
#include "y.tab.h"
```

- Includes the header generated by `yacc -d expression.y`.
- This provides the `NUMBER` token value shared by the lexer and parser.
- The header is generated during the build and is intentionally not committed.

```c
int yyparse(void);
extern int yylval;
```

- `yyparse` is the parser function generated by Yacc.
- `yylval` is the shared semantic-value variable. The lexer stores a parsed
  integer in it before returning `NUMBER`.

```c
int yylex(void)
{
```

- Defines the lexer function expected by the generated parser.

```c
    int value;
    int character;
```

- `value` stores a complete integer read from input.
- `character` stores the current input character.

```c
    do {
        character = getchar();
    } while (character == ' ' || character == '\t');
```

- Reads one character at a time.
- The loop skips spaces and horizontal tabs between tokens.

```c
    if (character == EOF || character == '\n') {
        return character;
    }
```

- Returns end-of-file or newline directly to the parser.
- Newline is a grammar token because the `input` rule requires it.

```c
    if (character >= '0' && character <= '9') {
        ungetc(character, stdin);
        if (scanf("%d", &value) != 1) {
            return 0;
        }
        yylval = value;
        return NUMBER;
    }
```

- Checks whether the first character begins a decimal integer.
- `ungetc` puts that first digit back so `scanf` can read the entire number.
- `scanf("%d", &value)` reads the integer.
- Returning `0` reports that no valid token could be read.
- `yylval = value` passes the integer's semantic value to the parser.
- Returning `NUMBER` tells the parser which token was found.

```c
    return character;
}
```

- Returns punctuation such as `+` and `-` as their literal character tokens.
- The closing brace ends `yylex`.

```c
void yyerror(const char *message)
{
    fprintf(stderr, "Parse error: %s\n", message);
}
```

- Defines the parser's error callback.
- Writes a readable error message to standard error.

```c
int main(void)
{
    return yyparse();
}
```

- Defines the program entry point.
- Starts parsing standard input and returns Yacc's status code to the shell.

### `Makefile`

```make
CC ?= cc
CFLAGS ?= -Wall -Wextra -std=c99
```

- Sets the C compiler to `cc` unless the caller supplied `CC`.
- Enables common warnings and C99 mode unless the caller supplied `CFLAGS`.

```make
expression: y.tab.c expression.c
	$(CC) $(CFLAGS) -o $@ y.tab.c expression.c
```

- Declares the `expression` executable target.
- The target depends on the generated parser and the hand-written glue code.
- The indented command compiles and links both C files.
- `$@` expands to the target name, `expression`.

```make
y.tab.c y.tab.h: expression.y
	yacc -d expression.y
```

- Declares both generated files as outputs of `expression.y`.
- `yacc -d` generates the parser source and its token header.

```make
clean:
	rm -f expression y.tab.c y.tab.h
```

- Defines a cleanup target.
- Removes the executable and generated parser files.
- `-f` makes removal succeed even when a file does not exist.

```make
.PHONY: clean
```

- Marks `clean` as a command name rather than a file target.

## Build and run

From this directory:

```sh
make
printf '1 + 1 - 3\n' | ./expression
make clean
```

Generated files and the executable are build artifacts and are not part of the
repository.
